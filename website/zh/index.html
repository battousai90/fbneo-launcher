专为 FinalBurn Neo 模拟器打造

FBNeo Launcher 是一个前端：它负责查找、校验和整理你的 ROM 游戏集，然后交给 FinalBurn Neo 来实际模拟运行。模拟器是由独立团队维护的另一个项目——本启动器可以为你下载它的最新版本。

在 Linux 上我们更进一步：FinalBurn Neo 官方团队已不再维护 SDL2/Linux 版本，导致部分系统（Game Boy Advance、Bally Astrocade）悄悄地不再生成游戏列表。我们每天跟踪他们的上游仓库，发布自己修复过的构建版本，让所有系统开箱即用地被覆盖。

ROM 管理

内置 RomVault 式工作流

每个 ROM 都通过重新计算 CRC32 并与 FinalBurn Neo 官方 DAT 文件比对来校验——绝不轻信文件名或压缩包内记录的数值。

  • 通过 DAT 的 CRC 校验审计 ROM 完整性
  • 检测缺失、损坏或不完整的 ROM
  • 从现有库自动重建游戏集
  • 递归导入 ROM
  • 生成缺失 ROM 和审计报告
  • 直接从 DAT 显示克隆/父级信息
  • 在库中查找重复的 ROM
  • 每个游戏集在进入输出前都会被校验

真正的 CRC 校验

每个压缩包的每个条目都会被解压并重算 CRC32，再与 DAT 比对。损坏的压缩包无法伪装成有效。

🔬

游戏库审计

告诉你哪些游戏集损坏，以及哪个文件出了问题，给出四种明确判定。

  • 正常 — 名称正确，数据正确
  • 名称错误 — 数据正确但命名有误
  • 损坏 — 文件存在但内容不符
  • 缺失 — 游戏集中根本没有
📥

输入 → 输出 重建

把下载的文件放进输入目录并点击「分析」。完整的游戏集会被移动，损坏的则用下载文件以及你现有游戏库中找到的零件重建。

🛡️

绝不写入你的游戏库

游戏库仅作为只读的零件来源。结果会写入另一个按 DAT 结构组织的输出目录，最坏的情况也不过是删掉一个文件夹。

🗜️

zip、7z、rar、tar

读取你下载的任何格式——包括固实压缩的 7z，一次遍历即可取出。始终输出干净、扁平的 ZIP 游戏集，这是模拟器唯一能加载的格式。

⚡

增量扫描

本地 SQLite 数据库配合内容寻址缓存。重新扫描只处理大小或时间戳变化过的文件；DAT 更新也只重新校验真正改动过的游戏集。

📋

可导出的报告

将缺失 ROM 清单或完整审计结果保存为按系统分组的文本报告，并附上每个待补文件的 CRC 与大小。

🔄

DAT 工具

直接从你的 FinalBurn Neo 可执行文件生成 DAT、刷新数据库，或下载最新的 FBNeo 版本——全部在应用内完成。

Linux 游戏 PC 与 SteamOS

客厅里也自在

为 Linux 游戏主机和客厅中的 SteamOS 设备而打造：一个用键盘和鼠标操作的真正桌面界面，而手柄则留给游戏本身。

🎮

SteamOS 与 Steam Machine（Steam Box）

SteamOS 基于 Arch，系统分区为只读，因此 Flatpak 是其官方支持的桌面软件安装方式。Flatpak 包可直接装入桌面模式，无需解锁系统，也不必碰 pacman。

🕹️

键鼠浏览，手柄游玩

在 25,000 款游戏中查找是键盘的活儿，启动器正是围绕这一点设计的。游戏启动时手柄支持已经开启，手柄配置也会保存并复用。

📺

从列表到游戏只需两次点击

不必层层翻找菜单：搜索、点击、开玩。把启动器作为非 Steam 游戏添加到 Steam，即可从游戏模式启动。

从源码构建

在 Debian 或 Ubuntu 上只需三条命令

# 1 — dependencies
sudo apt install -y build-essential cmake pkg-config \
  libgtkmm-3.0-dev libpugixml-dev nlohmann-json3-dev \
  libcurl4-openssl-dev libzip-dev libarchive-dev \
  zlib1g-dev libsqlite3-dev

# 2 — build
git clone https://github.com/battousai90/fbneo-launcher.git
cd fbneo-launcher && cmake -S . -B build && cmake --build build -j$(nproc)

# 3 — run
cd build && ./fbneo-launcher

更想要安装包？./scripts/package.sh 会在 dist/ 中生成 AppImage、.deb、tar 包和 Flatpak 捆绑包——正是发布流程所运行的同一个脚本。
